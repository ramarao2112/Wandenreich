# TC-004: MASS-ASSIGNMENT

## Overview
- **Rule ID:** `TC-004`
- **Rule Name:** `MASS-ASSIGNMENT`
- **Severity:** `Error`
- **Target:** Endpoint request bodies (`body: [...]`)

## Trigger
An endpoint request body (`POST`, `PUT`, `PATCH`) lists one or more server-controlled or sensitive fields:
1. **Primary Key:** `id`
2. **Ownership Field:** The resource's declared ownership reference (e.g. `owner_id -> User.id`)
3. **Credential Fields:** `password`, `password_hash`, `access_token`, etc.

## Rationale
Allowing clients to specify primary keys, ownership fields, or credentials in request bodies enables mass assignment / parameter tampering attacks. Attackers can forge resource IDs, hijack resource ownership by assigning other users' IDs, or tamper with security attributes.

## Fix Options
- **Remove Server-Controlled Fields from Body (Automated Fix):**
  Remove `id`, `owner_id`, or credential fields from the `body: [...]` list.
  ```trust
  # Before:
  body: [destination, owner_id]

  # After:
  body: [destination]
  ```
  Ownership will automatically be assigned from the authenticated caller's verified `current_user.id` on creation (`POST`), and primary keys are server-generated UUIDs.
