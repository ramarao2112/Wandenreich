# TC-003: SENSITIVE-LEAK

## Overview
- **Rule ID:** `TC-003`
- **Rule Name:** `SENSITIVE-LEAK`
- **Severity:** `Error`
- **Target:** Endpoint response projections (`returns:`)

## Trigger
An endpoint returns sensitive or credential fields without permitted authorization:
1. **Credential Exposure:** An endpoint returns a reserved credential field (`password`, `password_hash`, `access_token`, `refresh_token`, `api_key`, `private_key`, `jwt_secret`). Credential fields are never permitted to be returned, even if declared in `expose: [...]`.
2. **Unexposed Sensitive Field:** An endpoint returns an ordinary field marked `[sensitive]` (such as `ssn`) without an explicit `expose: [field]` declaration.
3. **Unprojected Whole Resource:** An endpoint returns the full resource (e.g. `returns: User`) which includes sensitive or credential fields without explicit field selection.

## Rationale
Returning passwords, password hashes, tokens, or sensitive user data in API responses leads to credential exposure, identity theft, and severe compliance violations. Response models must strictly restrict serialized fields to safe subsets.

## Fix Options
1. **Narrow the Projection (Recommended):**
   Explicitly specify safe fields in the returns projection:
   ```trust
   endpoint GET /users/{id}:
     resource: User
     auth: required
     returns: User [id, email]
   ```
2. **Explicitly Expose Ordinary Sensitive Fields:**
   If business logic genuinely requires returning an ordinary sensitive field (like `ssn`), declare it explicitly in `expose:`:
   ```trust
   endpoint GET /users/{id}:
     resource: User
     auth: required
     expose: [ssn]
     returns: User [id, email, ssn]
   ```
   *(Credential fields like `password_hash` can never be exposed.)*
